## 二、Agent 架构与范式

### 2.1 RATED：可靠性感知的 AI Agent 工具检索

**论文**：[RATED: Reliability-Aware AI Agent Tool Retrieval via Execution Dynamics](https://arxiv.org/abs/2610.13889)  
**会议**：CIKM 2026

**核心问题**：
现有 Agent 在选择工具时主要基于功能匹配，忽视工具的可靠性（如 API 稳定性、响应时间、错误率）。

**解决方案**：
RATED 框架引入执行动态（Execution Dynamics）作为工具选择的关键维度：
1. **历史成功率**：工具过去的执行成功概率
2. **响应延迟分布**：P50/P95/P99 延迟
3. **错误模式**：常见错误类型及恢复策略
4. **成本模型**：每次调用的计算/金钱成本

**实验结果**：
在 10 个真实 Agent 任务上，RATED 相比基线方法：
- 任务成功率提升 18%
- 平均响应时间降低 32%
- 工具调用失败率降低 45%

**💡 对你的价值**：如果你在构建生产级 Agent 系统，RATED 的思路值得借鉴。建议为每个工具维护一个可靠性档案，在工具选择时综合考虑功能、性能、成本。

### 2.2 AgentSWE：编码 Agent 能构建你想要的 Agent 吗？

**论文**：[AgentSWE: Can Coding Agents Build the Agent You Actually Want?](https://arxiv.org/abs/2610.13361)  
**热度**：HuggingFace Daily Papers 第3名（201 upvotes）

**研究问题**：
用户能否通过自然语言描述，让编码 Agent（如 Claude Code、Cursor）自动生成符合需求的 Agent 系统？

**关键发现**：
1. **需求歧义**：80% 的 Agent 需求描述存在歧义，导致生成的系统不符合预期
2. **架构理解差距**：用户对 Agent 架构（如 ReAct、Plan-and-Execute）的理解不足
3. **迭代成本**：平均需要 5.3 轮迭代才能生成可接受的 Agent

**建议工作流**：
```
1. 明确任务边界 → 2. 选择架构模式 → 3. 定义工具集 → 4. 生成原型 → 5. 测试迭代
```

**💡 对你的价值**：不要期望编码 Agent 一次性生成完美的 Agent 系统。建议先学习 Agent 架构基础知识（如 ReAct、Function Calling），然后用结构化提示引导生成。

### 2.3 X-AgentRed：多服务生态中的 Agent 红队测试

**论文**：[X-AgentRed: Red-Teaming Personal Agents in Evolving Multi-Service Ecosystems](https://arxiv.org/abs/2610.13886)

**核心挑战**：
现代 Agent 通常集成多个服务（邮件、日历、文件存储等），攻击面大幅增加。

**红队测试框架**：
1. **服务边界攻击**：通过一个服务漏洞访问其他服务
2. **权限升级**：利用服务间信任关系获取更高权限
3. **数据泄露链**：通过多个服务的组合泄露敏感信息

**防御建议**：
- 最小权限原则：每个服务只授予必要权限
- 服务隔离：关键服务使用独立沙箱
- 审计日志：记录所有跨服务调用

**💡 对你的价值**：如果你在部署多服务 Agent，务必进行安全审计。建议从 X-AgentRed 的测试用例开始，评估你的 Agent 是否存在类似漏洞。

### 2.4 Humanize Olympiad Agents：多 Session 工作流

**论文**：[Humanize Olympiad Agents: A Multi-Session Workflow for Olympiad Problem Solving](https://arxiv.org/abs/2610.13632)

**创新点**：
将复杂的数学竞赛问题求解分解为多个 Session：
1. **Solve Session**：初始解题尝试
2. **Review Session**：审查解题过程，发现错误
3. **Wiki Session**：查阅相关知识，补充背景
4. **Verify Session**：验证最终答案

**关键洞察**：
- 单 Session 解决复杂问题的成功率仅 23%
- 多 Session 工作流将成功率提升至 67%
- 每个 Session 专注于单一职责，减少上下文污染

**💡 对你的价值**：对于复杂任务，不要试图在单个 Session 中完成。建议采用多 Session 工作流，每个 Session 有明确的目标和退出条件。

### 4.1 Claude Code 上下文压缩控制

**问题**：
Claude Code 在长对话中会自动压缩上下文，可能导致重要信息丢失。

**解决方案**：
通过配置控制上下文压缩行为：

```bash
# 禁用自动压缩
export ANTHROPIC_CONTEXT_COMPACT=off

# 设置压缩阈值（Token 数）
export ANTHROPIC_CONTEXT_COMPACT_THRESHOLD=100000

# 手动触发压缩
claude compact --force
```

**最佳实践**：
1. 在关键任务前手动保存上下文快照
2. 使用 `/compact` 命令在合适时机压缩
3. 对于长任务，拆分为多个 Session

**💡 对你的价值**：掌握上下文压缩控制，可以避免关键信息丢失，提高 Claude Code 在长任务中的可靠性。

## 五、值得深读的研究

### 5.1 Thinking Inertia: LLMs Keep Thinking When Told Not To

**论文**：[Thinking Inertia](https://arxiv.org/abs/2610.11765)  
**机构**：Stanford University  
**热度**：HuggingFace Daily Papers 第2名（215 upvotes）

**研究方法**：
1. 设计"停止思考"提示，要求模型直接给出答案
2. 在 10 个推理任务上测试 5 个主流 LLM
3. 分析模型的"思考链"长度和答案质量

**核心发现**：
- **思考惯性**：即使被要求"不要思考"，模型仍会生成 3-5 步推理
- **质量权衡**：强制停止思考导致准确率下降 15-30%
- **模型差异**：GPT-4 比 Claude 更擅长"停止思考"

**启发**：
- 推理能力是大模型的内在特性，难以简单关闭
- 在设计提示时，应利用而非对抗这一特性
- 对于简单任务，可以接受"过度思考"以换取可靠性

**💡 对你的价值**：理解"思考惯性"可以帮助你设计更好的提示。对于简单任务，不要过度限制模型的推理；对于复杂任务，鼓励充分思考。

### 5.2 GroundingPI: 物理智能基础模型

**论文**：[GroundingPI](https://arxiv.org/abs/2609.39601)  
**机构**：XPENG AI  
**热度**：HuggingFace Daily Papers 第1名（246 upvotes）

**研究方法**：
1. 收集 100 万条机器人操作数据
2. 训练视觉-动作基础模型
3. 在 50 个机器人任务上评估泛化能力

**核心发现**：
- **视觉原语**：模型学习到通用的视觉-动作映射
- **零样本泛化**：在新物体和新场景上成功率 >70%
- **少样本微调**：10 条数据即可适应新任务

**启发**：
- 物理智能需要大规模真实世界数据
- 基础模型可以显著降低机器人任务的开发成本
- 视觉-动作联合训练是关键

**💡 对你的价值**：如果你从事机器人或自动化领域，GroundingPI 的思路值得借鉴。建议关注视觉-动作联合训练的方法。

### 5.3 Scaling Agentic Data for Long-Horizon Terminal Intelligence

**论文**：[Scaling Agentic Data](https://arxiv.org/abs/2610.13166)  
**机构**：Alibaba  
**热度**：HuggingFace Daily Papers 第4名（133 upvotes）

**研究方法**：
1. 构建 100 万条长程 Agent 轨迹数据
2. 训练 Agent 模型，支持 100+ 步任务
3. 评估在复杂任务上的表现

**核心发现**：
- **数据规模**：Agent 性能与训练数据量呈对数线性关系
- **长程依赖**：模型需要学习 50+ 步的依赖关系
- **终端智能**：模型能够规划并执行多步任务直到目标达成

**启发**：
- Agent 训练需要大规模高质量轨迹数据
- 长程任务需要专门的架构和训练方法
- 数据质量比模型规模更重要

**💡 对你的价值**：如果你在训练 Agent 模型，建议优先构建高质量的轨迹数据集。可以使用现有 Agent 系统生成数据，然后人工筛选和标注。

### 5.4 AI Models Can Provably Hide Arbitrary Capabilities

**论文**：[AI Models Can Provably Hide Arbitrary Capabilities](https://arxiv.org/abs/2610.13928)
