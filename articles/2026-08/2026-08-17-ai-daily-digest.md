## 🏗️ 二、Agent 架构与范式

### 2.1 OmniScientist：全模态全学科 AI 科学家

**论文：** arXiv:2608.13558 | 30 页 | 2026-08-13

**核心架构：**
- **端到端全模态输入：** 直接处理图像、信号、音频、视频、3D 结构、轨迹、表格、公式、图表等 9 种模态的原始数据
- **感知层 + 3 个自主 Agent：** 感知层负责从原始数据提取证据；Idea Agent 负责假说生成；Experiment Agent 负责实验设计执行；Writeup Agent 负责论文撰写
- **确定性流水线：** 观察→研究问题→实验决策→最终结论，全链路可追溯
- **代码化验证：** 新颖性筛查、统计有效性、执行溯源、数值可追溯性全部通过代码执行

**评估结果：**
- 36 个真实数据案例，跨 5 个学科族、4 种证据类型
- 全部 36 例完成从原始数据到编译论文的完整路径
- 平均论文评分 6.3（满分 10）
- 与仅接收预计算特征的盲变体对比，直接感知在所有 7 个评估维度上均有提升，85% 的头对头判断胜出

**💡 对你的价值：** 这代表了 AI 科学家的最新范式——不是让 LLM 读论文做推理，而是让 AI 直接从原始实验数据出发做完整科研。如果你在做科研自动化，这个架构值得深入参考。

### 2.2 MARC：开源临床多 Agent 推理框架

**论文：** arXiv:2608.13476 | GitHub: Penn-RAIL/MARC-v1

**核心设计：**
- **角色专业化 Agent：** 提取 Agent、推理 Agent、答案生成 Agent、评估 Agent
- **显式上下文传递：** 每个 Agent 之间有明确的上下文接口，中间输出可追溯
- **Decomposer 模块：** 从自然语言描述自动生成任务特定的 Agent 提示词，消除手工提示工程

- **YAML 配置驱动：** 无需修改代码，纯配置文件控制全流程

**💡 对你的价值：** MARC 的设计模式（角色分工 + 显式上下文 + 自动提示生成 + YAML 配置）是构建领域多 Agent 系统的优秀参考。特别是 Decomposer 模块的思路——用自然语言描述任务，自动生成 Agent 提示——可以大幅降低多 Agent 系统的搭建门槛。

### 2.3 RippleMem：从孤立检索到联想式回忆

**论文：** arXiv:2608.13334 | 22 页

**核心创新：**
- **问题诊断：** 现有 Agent 记忆系统的瓶颈不是存储，而是"在相关信息分散在多次交互中时，如何恢复正确的证据集"
- **联想式回忆机制：** 受心理学中"线索依赖情景检索"和"联想补全"启发
  1. 将交互历史存储为"线索丰富的情景记忆单元"
  2. 组织为以事件为中心的记忆图
  3. 查询时先通过混合线索召回相关记忆锚点
  4. 从锚点沿语义和结构关联扩展，恢复缺失的支撑证据

**评估结果：**
- LoCoMo 数据集：LLM-as-a-Judge 准确率提升 3.95%
- LongMemEval-S 数据集：提升高达 11.87%
- 图构建成本降低约 30 倍

**💡 对你的价值：** 如果你在做长期对话 Agent 或需要跨会话记忆的助手，RippleMem 的"锚点→联想扩展"机制比传统 RAG 的"一次性检索"更有效。关键洞察：初始召回的记忆不仅作为答案上下文，还作为补全证据的线索。

### 2.4 AI Agent 评估：更像"工程优化器"而非"自主研究者"

**论文：** arXiv:2608.13417 | 7 个前沿模型 × 36 个长周期任务

**核心发现：**

| 维度 | 发现 |
|------|------|
| 行为模式 | 更像工程优化器，能制定和实施实用方案 |
| 稳定性 | 跨运行差异很大，同一模型表现不一致 |
| 创新性 | 最强方案主要是适配或组合已有技术，真正方法论创新罕见 |
| 经验复用 | 可以帮助也可能误导后续决策 |
| 瓶颈 | 相似最终结果背后有不同的过程瓶颈 |
| Harness 影响 | 框架设计显著影响性能稳定性 |

**💡 对你的价值：** 这篇论文给所有做 Agent 的人泼了一盆冷水：当前 Agent 本质上是"高级工程优化器"，不是真正的自主研究者。设计 Agent 系统时，应该把重点放在经验管理和 Harness 稳定性上，而不是期待 Agent 自发产生创新方案。

### 2.5 GEM：推理增强的生成式嵌入模型

**论文：** arXiv:2608.13200

**核心创新：**
- 传统检索器依赖查询和文档的表面匹配，但用户表达需求的方式和检索器解释方式之间存在鸿沟
- GEM 在单一模型中统一生成和嵌入：先对查询进行推理，再附加嵌入 token 编码增强上下文
- 支持测试时计算扩展（test-time compute scaling）：通过 prompting 进一步提升检索性能

**💡 对你的价值：** 如果你的 RAG 系统检索质量不够好，GEM 的思路值得借鉴——让检索器先"理解"用户意图再编码，而不是直接做字面匹配。这对复杂查询场景（如多条件筛选、隐含意图）特别有效。

### 4.2 RAG 系统优化技巧

基于本周论文 GEM 和 RippleMem 的启发：

1. **查询推理前置：** 在检索前先让 LLM 对查询进行推理扩展（GEM 思路）
   ```
   用户查询 → LLM 推理扩展 → 生成多个检索视角 → 并行检索 → 融合排序
   ```

2. **联想式记忆扩展：** 不要只做一次性检索，让已召回的结果作为新线索继续扩展
   ```
   初始检索 → 召回锚点 → 沿语义关联扩展 → 补全缺失证据
   ```

3. **选择性置信度：** 参考 SciFigBench 的发现，让模型学会"说不知道"比强行回答更重要

### 4.3 多 Agent 系统搭建清单

基于 MARC 和本周 Agent 论文的实践经验：

- [ ] **角色定义：** 每个 Agent 有明确的专业角色和职责边界
- [ ] **上下文接口：** Agent 之间用结构化格式传递上下文（不要依赖隐式共享）
- [ ] **可追溯性：** 每个 Agent 的中间输出都要记录，便于故障定位
- [ ] **配置驱动：** 用 YAML/JSON 配置而非硬编码
- [ ] **经验管理：** 记录哪些经验帮助了决策，哪些误导了决策
- [ ] **稳定性测试：** 同一任务跑多次，检查输出一致性

**论文：** arXiv:2608.13558 | 项目页：omni-scientist.github.io

- 平均论文评分 6.3/10

**启发：** AI 科学家的瓶颈不在推理能力，而在"感知带宽"——能直接从多少种原始数据中提取有效证据。这提示我们：多模态不是锦上添花，而是科研自动化的基础设施。

### 5.2 QuoteBench：匹配分数如何掩盖命令路径失败

**论文：** arXiv:2608.13547 | 项目页：quotebench.lsamc.website

**研究方法：**
- 56 个一次性任务，14 个事故衍生族
- 交叉"生成契约"和"执行传输"，围绕一个故意未转义的解析器
- 8 个同窗口配置的重现实验

**核心发现：**
- 在解析器中添加转义点后，相同回复的成功率下降 55.4-73.2 个百分点
- GPT-5.6-sol 的匹配分差仅 -3.6 分，但实际隐藏了 -64.3 分的损害和 +60.7 分的补偿
- 原始生成已接近饱和，边界适配才是模型间的真正差异

**启发：** 评估 LLM 编码 Agent 时，"匹配分数"远远不够。必须报告模型配置、生成契约、执行路径、操作点和最终状态验证器。这对所有做 Coding Agent 评估的团队都是重要警示。

---

### 5.3 SAEVerbalizer：让 LLM 自己解释稀疏自编码器特征

**论文：** arXiv:2608.13538

**研究方法：**
- 将 SAE 解码方向注入 LLM 的表征中
- 微调 LLM 的下游层以生成被注入特征的自然语言解释
- 测试泛化性：未见特征、跨 SAE 字典迁移、跨 LLM 迁移

**核心发现：**
- 学习到的口头化能力可以泛化到未见过的特征
- 可以跨独立训练的 SAE 字典迁移
- 通过轻量适配器可以扩展到其他 LLM 的 SAE 特征
- 注入多个方向产生组合含义解释，反转单个方向产生对应含义偏移

**启发：** 这是可解释性领域的重要突破——不再需要从外部观察推断特征含义，而是让模型自己"说出"特征代表什么。这对理解和调试大模型行为有直接价值。

### 5.4 AI 安全设计的 Scaling Law：规则 vs 品格

**论文：** arXiv:2608.13345 | 已被 AIES 2026（AAAI/ACM AI 伦理与社会会议）接收

**研究方法：**
- 将 AI 安全设计建模为资源分配问题：α ∈ [0,1] 分配给"品格塑造"（RLHF/Constitutional AI）vs"规则执行"（输出过滤器/安全分类器）
- 引入规模依赖的过滤器退化、共模失败和"品格脆弱性"
- 乘法 Pareto 损害模型 + CVaR 尾部风险分析 + 蒙特卡洛模拟

**核心发现：**
- 最优 α* 随部署规模 T 增长弱向品格塑造偏移（+0.01 到 +0.21）
- **主导参数是基线品格脆弱性率**，在其范围内移动 α* 达 0.50——远超尾部严重性、过滤器质量或共模失败概率的影响
- CVaR 和期望损害最优值在大 T 时收敛

**启发：** AI 安全架构决策与其说取决于部署规模，不如说取决于品格塑造在分布式偏移下的可靠性。这意味着：如果你的 RLHF 训练不够稳健（品格脆弱性高），无论部署规模多大，都应该更依赖规则执行（输出过滤）。

### 5.5 SciFigBench：VLM 在科学图表上的行为可靠性

**论文：** arXiv:2608.13267 | 项目页：scifigbench.nlp4sci.com

**研究方法：**
- 250 张科学图表，600+ 小时人工标注
- 通过图像变换、推理问题、抵抗探针、标题偏差探针、选择性模糊等生成 34,000+ 评估设置
- 提出 A-R-I 框架：承认（Admittance）证据不足、抵抗（Resistance）误导上下文、从部分信息谨慎推断（Inductance）

**核心发现：**
- GPT-5.2 描述质量最高（MQM 91.6）但 96% 的情况下会幻觉不可读内容
- Gemini 3.1 Pro 能力相当（MQM 90.2）但 71% 的情况下承认不确定性，抵抗得分最高（0.91）
- **高感知和推理准确率不保证行为可靠性**

**启发：** 选择科学/专业场景的 VLM 时，不能只看准确率。"知道自己不知道什么"的能力同样重要。Gemini 3.1 Pro 在行为可靠性上优于 GPT-5.2，这对科学工作流部署是关键参考。

### 5.6 Gricean Retreat：LLM 的知识边界与指称特异性

**论文：** arXiv:2608.13484

**研究方法：**
- 基于 T-REx 的基准测试，变化实体熟悉度和指称特异性
- 探测两个问题：(i) 模型激活是否编码了指称是否在知识边界内；(ii) 模型是否预判了即将生成的指称的特异性

**核心发现：**
- 两个信号都存在，但在生成中未被协调
- 模型压倒性地偏好特异性指称，即使实体未知
- 即使提供了正确的泛化替代选项，模型仍然选择具体指称
- "Gricean 撤退"的基础设施存在，但执行它的策略不存在

**启发：** LLM 的"幻觉"问题不仅仅是"不知道还瞎说"——更深层的是模型缺乏"在不确定时退回到更安全、更笼统的说法"的能力。这为减少幻觉提供了一条新路径：不是让模型知道更多，而是训练它在不确定时"说得更笼统"。

### 5.7 Mixture of Training (MoT)：模块化预训练

**论文：** arXiv:2608.13277 | 已被 COLM 2026 MOSS Workshop 接收

**研究方法：**
- 将目标 Transformer 分成连续的层块
- 每个块在冻结的预训练对齐器脚手架内独立训练
- 训练完成后重组，可选的短端到端适配

**核心发现：**
- 在 1.3B Gemma 风格模型上验证：独立训练的深度切片可以重组为可用的语言模型
- 质量对齐调度达到与单体基线相同的困惑度
- 对齐调度处理更多聚合 token，但在对齐器准备后关键路径更短

**启发：** 这为"分布式训练"提供了新思路——不是数据并行，而是"层块并行"。每个层块可以独立训练，然后组合。这对资源受限的团队特别有价值：你可以分别训练模型的不同部分，最后组装。
