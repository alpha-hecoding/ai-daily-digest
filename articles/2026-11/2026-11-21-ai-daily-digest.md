### 1.3 NVIDIA Nemotron-Labs-Sigma：扩散语言模型

**发布方：** NVIDIA  
**参数规模：** 3B / 8B  
**架构创新：** 连续扩散语言模型

NVIDIA 发布了 Nemotron-Labs-Sigma，这是一系列**连续扩散语言模型**，与传统自回归模型不同，它在 16 维连续潜在嵌入空间中执行去噪。

**核心技术：**
- 14 个检查点，覆盖 3B 和 8B 两种规模
- 支持少步蒸馏和轨迹引导
- 投机解码加速最高 3.46 倍

**与传统 LLM 对比：**

| 特性 | 自回归模型 | 扩散语言模型 |
|------|-----------|-------------|
| 生成方式 | 逐 token 生成 | 并行去噪生成 |
| 推理速度 | 受限于序列长度 | 可并行，潜在加速 |
| 质量 | 成熟稳定 | 实验性，特定任务有优势 |
| 生态支持 | 完善 | 新兴，工具链待完善 |

**💡 对你的价值：** 扩散语言模型是 LLM 架构的重要探索方向。如果你对推理速度有极致要求，可以关注这一技术路线。目前更适合研究用途，生产环境建议观望。

## 二、Agent 架构与范式 🤖

### 2.1 【重磅论文】Seer：用共享决策模型引导小型深度研究 Agent

**论文：** arXiv:2611.26423  
**作者：** Yuhao Zhou 等（四川大学）  
**核心贡献：** 让 4B/9B 小模型在 GAIA 基准上性能翻倍

**问题背景：**
深度研究 Agent 需要反复决定搜索什么、阅读什么、验证什么。通常依赖大型云端模型，但隐私和本地控制需求推动了在用户设备上运行 Agent 的趋势。然而，设备上的小模型面临推理时引导的三大障碍：
1. 通过真实执行探索替代方案会增加工具调用
2. 提示自我评估受限于 Agent 自身判断
3. 模型特定引导需要重复适配

**Seer 的解决方案：**
```
┌─────────────────────────────────────────────────────────┐
│                    Seer 架构                             │
├─────────────────────────────────────────────────────────┤
│  共享研究轨迹语料库                                        │
│         ↓                                                │
│  ┌──────────────────┐    ┌──────────────────┐          │
│  │ 工具响应模拟器     │    │ 价值估计器        │          │
│  │ (Tool-Response   │    │ (Value Estimator) │          │
│  │  Simulator)      │    │                   │          │
│  └────────┬─────────┘    └────────┬──────────┘          │
│           ↓                       ↓                      │
│  ┌────────────────────────────────────────────┐         │
│  │        本地引导（无需真实执行候选动作）        │         │
│  └────────────────────────────────────────────┘         │
│         ↓                                                │
│  ┌──────────────────┐                                   │
│  │ 小型研究 Agent    │ ← 只执行选中的动作                  │
│  │ (4B/9B 模型)     │                                   │
│  └──────────────────┘                                   │
└─────────────────────────────────────────────────────────┘
```

**核心发现：**
- GAIA 准确率：Qwen3.5-4B 从 13.6% → 41.7%（+28.1pp）
- GAIA 准确率：Qwen3.5-9B 从 22.3% → 50.5%（+28.2pp）
- 模拟器和价值估计器可跨 Agent 复用，无需重新训练
- 更广泛的候选覆盖可以弥补不完美的模拟

**💡 对你的价值：** 这是**小模型 Agent 的重大突破**。如果你想在本地运行深度研究 Agent，Seer 框架可以让 4B 模型达到接近大模型的效果。代码开源后值得立即尝试。

### 2.2 【重磅论文】Agent 记忆管理：多少记忆才算够？

**论文：** arXiv:2611.26361（IAAI 2027 Oral）  
**作者：** K. R. Jayaram 等（IBM）  
**核心发现：** 合适的记忆量是模型的属性，而非记忆的属性

**问题背景：**
LLM Agent 在长期任务中以重复、程序化的方式失败：API 分页错误、解析错误实体、在未被要求时回答。

**解决方案：altk-evolve 管道**
```
Agent 轨迹 → 挖掘经验教训（每集 1-3 条）→ 合并为指南 → 推理时注入
```

**核心实验结果：**

| 模型 | 基线 | 全量指南 | 精选子集 | 最佳策略 |
|------|------|---------|---------|---------|
| DeepSeek-V3.2 | 92% | +9.5pp | - | 全量更好 |
| gpt-oss-120b | 39.9% | 51.2% | **55.4%** | 精选更好 |

**关键洞察：**
1. **强模型**：随着指南增加持续改进，可使用全量记忆
2. **弱模型**：从精选子集中获益更多，过多记忆反而干扰
3. **陷阱案例**：
   - 高支持度指南可能适得其反
   - 合并过程中来源信息被无声丢弃
   - API 错误被吞没，产生看似合理的日志但所有任务失败

**💡 对你的价值：** 如果你在构建长期 Agent，这篇论文提供了实战经验。**不要盲目堆砌记忆**，根据模型能力调整记忆量。弱模型配合精选记忆 > 全量记忆。代码已开源（altk-evolve）。

### 2.3 MemFolder：结构化记忆折叠框架

**论文：** arXiv:2611.26427  
**代码：** https://github.com/xuyang-liu16/MemFolder

**问题：** 长期 Agent 积累大量外部记忆，导致存储、检索、响应生成成本增加。

**解决方案：**
```
┌────────────────────────────────────────────────────────┐
│                   MemFolder 架构                        │
├────────────────────────────────────────────────────────┤
│  原始记忆记录                                           │
│         ↓                                               │
│  ┌─────────────────────────────────────────────┐       │
│  │ RecordFolder                                 │       │
│  │ • 实体锚点接地                                │       │
│  │ • 渐进式选择代表性锚点                        │       │
│  │ • 语义+实体亲和力 + 时间链                     │       │
│  │ → 合并为更少的检索单元                        │       │
│  └─────────────────────────────────────────────┘       │
│         ↓                                               │
│  ┌─────────────────────────────────────────────┐       │
│  │ ContextFolder                                │       │
│  │ • 编码为紧凑文本                             │       │
│  │ • 验证反馈修正                               │       │
│  │ → 进一步缩短上下文长度                        │       │
│  └─────────────────────────────────────────────┘       │
└────────────────────────────────────────────────────────┘
```

**核心结果：**
- 在 Mem0 上，RecordFolder 用**减少 50% 的记录**保留了 99.0% 的原始性能
- 超过最强基线 1.9 个百分点

**💡 对你的价值：** 如果你的 Agent 面临记忆膨胀问题，MemFolder 提供了优雅的解决方案。**50% 记录减少，99% 性能保留**——这是非常实用的工程优化。

### 2.4 ClonAct：无路由器的上下文虚拟化架构

**论文：** arXiv:2611.26346  
**代码：** https://github.com/Viacol0916/ClonAct

**问题：** 管理跨多个 Agent 会话的并发任务会迅速耗尽人类注意力。但将所有上下文汇入单一线性会话会导致跨主题约束泄漏和队头阻塞。

**核心创新：**
- **Context MMU**：可插拔的单次非生成式上下文内存管理单元
- **Context Cells**：原地上下文单元格
- **Synaptic Bus**：足迹感知的突触总线，带隔离试验合并门
- **Shared Trunk**：波刷新的共享主干

**核心结果：**
- 真实冲突合并：从 33.3% → 63.3%
- Prompt token 减少：45.9%
- 持续涌流下完成率：95.0%

**💡 对你的价值：** 如果你需要在一个界面中管理多个并行任务（如同时处理多个代码仓库），ClonAct 的无路由器设计值得参考。

### 2.5 AutoMaster：自主后训练系统

**论文：** arXiv:2611.26510  
**代码：** https://github.com/RUCAIBox/AutoMaster  
**模型：** https://huggingface.co/collections/RUC-AIBOX/automaster

**核心思想：** 让同一个模型成为更好的老师

**问题：** 任务成功本身并不能说明后训练应该强化哪些行为。即使成功的教师轨迹也可能包含无根据的假设、无效的重复或肤浅的验证。

**解决方案：Skill-FT（技能引导微调）**
```
教师轨迹 → 轨迹分析 → 技能设计 → 数据选择 → 微调目标模型
                ↑___________________________|
                         反馈循环
```

**核心结果：**
- 在 Terminal、Search、软件工程任务上
- 4B 和 9B 目标模型平均性能提升：1.42-8.99 个百分点
- 教师、任务池、训练集大小、SFT 配方保持不变

**💡 对你的价值：** 这是**自主后训练的重要进展**。如果你有特定领域的 SFT 需求，AutoMaster 可以自动发现并强化有效行为，无需人工设计训练数据。

### 5.1 GLiDE：从推理教师蒸馏的快速校准决策模型

**论文：** arXiv:2611.26509  
**参数规模：** 0.4B - 27B

**研究方法：**
1. 基于 Qwen 混合语言模型构建
2. 移除全注意力层的因果掩码，实现双向交互
3. 多教师软目标蒸馏（包括推理模型）
4. 渐进式后训练
5. 无参数递归深度增加推理时计算

**核心发现：**
- GLiDE-27B：隐藏集分数 73.37，校准误差 2.1%
- 单 GPU 中位延迟：92.9ms
- 在 HuggingFace DI 基准上处于性能-参数 Pareto 前沿

**启发：** 决策模型可以在单次前向传播中完成推理，无需生成文本。这对于需要快速、置信度感知决策的场景（如搜索排序、推荐系统）非常有价值。

**💡 对你的价值：** 如果你需要低延迟的分类/排序任务，GLiDE 系列模型值得关注。27B 模型在单 GPU 上延迟不到 100ms。

### 5.2 WeVisForensics：自演化 Agent 用于全能 AI 生成视频检测

**论文：** arXiv:2611.21373  
**机构：** 腾讯  
**HuggingFace 热度：** 47 票（今日第一）

**研究方法：**
- 自演化 Agent 架构
- 多模态特征融合
- 持续学习机制

**核心发现：**
