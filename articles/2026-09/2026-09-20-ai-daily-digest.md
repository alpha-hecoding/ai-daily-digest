### 1.3 dQwen3.5：扩散语言模型的突破

**论文**：[arXiv:2609.20751](https://arxiv.org/abs/2609.20751)

**核心创新**：将 Qwen3.5 的混合注意力（Hybrid-Attention）架构适配为扩散语言模型（DLM），在 0.8B/2B/4B/9B 四个规模上验证。

**关键发现**：

| 对比维度 | 混合注意力 DLM | 全注意力 DLM |
|---|---|---|
| 达到同等训练 loss 所需 token | 约 50% | 100%（基线） |
| 解码行为 | 支持任意顺序解码 | 类似 |
| 并行解码性能 | 强 | 强 |

**技术解读**：这是一个重要突破。传统扩散语言模型需要全注意力 Transformer，但当前主流 LLM 已经转向混合注意力（交替使用 Attention 和 RNN 层）。dQwen3.5 证明了混合架构也能高效适配为 DLM，且训练效率翻倍。这意味着未来的扩散语言模型可以直接从最新的混合架构 LLM 出发，不需要回退到全注意力架构。

**💡 对你的价值**：
- **关注并行解码**：DLM 支持任意顺序解码，在批量生成场景下速度优势明显
- **训练成本**：如果你的场景需要微调语言模型，混合架构 DLM 是更高效的起点
- **前沿追踪**：扩散语言模型是 2026 年的重要研究方向，值得持续关注

## 二、Agent 架构与范式

### 2.1 ⭐ Coding Agent Harness 的组件级实证研究

**论文**：[arXiv:2609.20804](https://arxiv.org/abs/2609.20804) | 43 页

**这是本周最重要的 Agent 论文**。研究团队首次将 Coding Agent Harness 拆解为独立组件进行系统性评估，而非将其视为黑盒。

**实验设计**：
- 轻量级 Coding Harness，固定执行循环
- 变化三个组件：**规划（Planning）**、**动作空间（Action Space）**、**上下文管理（Context Management）**
- 4 个模型 × SWE-Bench Verified + Terminal-Bench 2.1
- 176 个匹配设置，5 种上下文管理策略，4 种上下文窗口预算

**核心发现**：

| 发现 | 详情 | 实践指导 |
|---|---|---|
| 上下文管理在窗口紧张时最有价值 | 大部分收益来自防止上下文溢出失败 | 小窗口模型必须配强上下文管理 |
| 规则裁剪 → LLM 摘要是最佳策略 | 先用规则裁剪再用 LLM 摘要效率最高 | 不要直接让 LLM 做全量摘要 |
| 可恢复裁剪无收益 | 让被裁剪内容可恢复增加了复杂度但模型很少使用 | 不要过度设计上下文恢复机制 |
| 规划对弱模型是脚手架，对强模型是省钱工具 | 弱模型靠规划提升准确率，强模型靠规划降成本 | 根据模型能力决定是否启用规划 |
| 预定义工具 vs Bash | 弱 Bash 能力模型需要预定义工具，强 Bash 模型用纯 Bash 更省 | 评估模型的 Bash 能力再决定工具设计 |

**轨迹级分析**：
- 上下文管理 → 延长执行轨迹但不改变 Agent 行为
- 规划 → 改变轨迹停止点
- 动作空间 → 改变代码编写的粒度

**💡 对你的价值**：
- **构建 Coding Agent 的团队**：这是目前最系统的 Harness 设计指南，建议精读
- **成本优化**：根据模型能力选择合适的组件组合，避免过度配置
- **实操建议**：先用规则裁剪再用 LLM 摘要，这个组合在大多数场景下是最优的

### 2.2 SoL-Pi：递归扩展自动研究循环

**论文**：[arXiv:2609.20519](https://arxiv.org/abs/2609.20519) | NVIDIA

**核心问题**：Coding Agent 从有监督的代码补全转向无人值守的全天候探索，Token 效率成为递归自我改进的关键瓶颈。

**方法**：在 Harness 层采用 RSI（递归自我改进）方法，跨越来越多和越来越多样的环境扩展自动研究循环。

**四个核心机制**：

| 机制 | 功能 |
|---|---|
| 动作执行优化 | 减少冗余动作 |
| 上下文压缩 | 压缩历史上下文 |
| 观察处理 | 优化观察信息的处理 |
| 委托阅读 | 将长文本阅读委托给专门模块 |

**性能对比**（EdgeBench 51 任务）：

| 对比 | Token 节省 | 成本节省 |
|---|---|---|
| vs 原生 Codex/Claude Code Harness | 44.7-49.0% | ~33% |
| vs Pi Harness | - | $4.36-5.71/小时 |
| 绝对节省 | - | $8.75-13.50/小时 |

**💡 对你的价值**：
- **长时间运行的 Agent**：如果你在用 Claude Code 或 Codex 做长时间任务，SoL-Pi 的机制可以直接借鉴
- **成本控制**：45% 的 Token 节省意味着显著的成本下降
- **代码**：[github.com/NVlabs/SoL-Pi](https://github.com/NVlabs/SoL-Pi)

### 2.3 RetireOPD：自退休在策略蒸馏

**论文**：[arXiv:2609.20784](https://arxiv.org/abs/2609.20784)

**问题**：多轮 Agent 用 RL 训练时，每条轨迹只有一个标量奖励，自蒸馏（OPD）可以提供密集的 token 级监督，但存在两个问题：
1. 特权信息本身不能让教师可靠
2. 教师监督的收益是阶段性的

**方法**：RetireOPD = 先优化解耦的技能条件教师 → 再用 RL+OPD 联合训练无技能学生 → 学生达到教师成功率的一定比例后自动"退休"教师

**性能提升**（Qwen2.5 1.5B-7B）：

| 基准 | 提升幅度 |
|---|---|
| ALFWorld 成功率 | +14.1% ~ +18.8% |
| WebShop 准确率 | +11.8% ~ +19.0% |
| 超越教师 | 所有设置均超越技能条件教师 |

**💡 对你的价值**：
- **训练 Agent 的团队**：这是训练多轮 Agent 的新范式，"自退休"机制避免了过度依赖教师
- **小模型增强**：1.5B-7B 模型通过此方法可以超越更大的教师模型
- **核心洞察**：教师不是越强越好，关键是知道什么时候该"退休"

### 2.4 On-Demand Attention：让模型自己决定何时召回

**论文**：[arXiv:2609.20734](https://arxiv.org/abs/2609.20734)

**核心思想**：全注意力解码在每一步都读取完整历史，但实际上并非每一步都需要全局信息。On-Demand Attention (ODA) 使用轻量级召回头，根据预测收益选择性调用全局注意力。

**技术亮点**：
- 只训练召回头，预训练权重不变
- 完整历史 KV Cache 保留供未来召回
- 在 vLLM 中实现 GPU 侧条件执行
- 支持混合注意力骨干（Qwen、Gemma）

**💡 对你的价值**：
- **长上下文推理加速**：如果你的应用涉及长上下文（Agent 对话、文档分析），ODA 可以显著加速
- **即插即用**：只训练一个小头，不需要重新训练整个模型
- **与 vLLM 集成**：已有生产级推理引擎的实现

### 2.5 JEPA-Anything：跨领域世界模型

**论文**：[arXiv:2609.20800](https://arxiv.org/abs/2609.20800)

**核心贡献**：提出领域无关的世界建模框架 JEPA-Anything，基于正交预测因子分解（OPF）。

**评估覆盖 7 个领域**：视觉、生物、临床轨迹、控制、分子动力学、物理场、天气

**关键结果**：
- 10 个动力学任务全部提升
- 干预性 Pong 单干预预测误差降低 34.8%
- 分子系统 100 步展开误差最低
- 生物因子提名干预在细胞共培养、类器官、肿瘤片段、小鼠实验中获得支持
- 潜在轨道模式恢复开普勒缩放指数（拟合斜率 -1.4991）

**💡 对你的价值**：
- **科学 AI 方向**：这是世界模型走向通用化的重要一步
- **跨领域迁移**：OPF 的因子分解思路可以借鉴到其他需要多领域建模的场景
- **代码**：[github.com/Gen-Verse/JEPA-Anything](https://github.com/Gen-Verse/JEPA-Anything)

## 五、值得深读的研究

### 5.1 ⭐ An Empirical Study of Harness Design for Coding Agents

**论文**：[arXiv:2609.20804](https://arxiv.org/abs/2609.20804) | 43 页

**研究方法**：组件级消融实验，固定执行循环，变化规划/动作空间/上下文管理

**核心发现**：
1. 上下文管理在窗口紧张时价值最大，收益主要来自防止溢出
2. 规则裁剪 → LLM 摘要是最佳上下文管理策略
3. 规划对弱模型提升准确率，对强模型节省成本
4. 弱 Bash 模型需要预定义工具，强 Bash 模型用纯 Bash 更省

**启发**：Agent Harness 不是越大越好，而是需要根据模型能力和任务特征做组件级优化。这为 Agent 工程从"手工作坊"走向"系统工程"提供了实证基础。

### 5.2 SoL-Pi: Recursively Scaling Auto-Research Loops

**论文**：[arXiv:2609.20519](https://arxiv.org/abs/2609.20519) | NVIDIA

**研究方法**：在 Harness 层做递归自我改进，跨多个环境扩展自动研究循环

**核心发现**：四个机制（动作执行、上下文压缩、观察处理、委托阅读）经选择后形成 SoL-Pi，在 51 任务 EdgeBench 上节省 45% Token 和 33% 成本

**启发**：Token 效率不是模型层的事，Harness 层的优化同样重要。对于长时间运行的 Agent，Harness 优化可能比模型升级更有性价比。

### 5.3 dQwen3.5: Hybrid-Attention Diffusion Language Models

**论文**：[arXiv:2609.20751](https://arxiv.org/abs/2609.20751)

**研究方法**：将混合注意力 Qwen3.5 适配为扩散语言模型

**核心发现**：混合架构 DLM 达到同等训练 loss 所需 token 约为全注意力 DLM 的一半

**启发**：扩散语言模型不再需要全注意力架构，最新的混合架构 LLM 可以直接作为起点。这降低了 DLM 的训练成本，也拓宽了 DLM 的架构选择。

### 5.4 RetireOPD: Self-Retiring On-Policy Distillation

**论文**：[arXiv:2609.20784](https://arxiv.org/abs/2609.20784)

**研究方法**：先训练技能条件教师，再用 RL+OPD 联合训练学生，学生达标后自动退休教师

**核心发现**：在 ALFWorld 和 WebShop 上，1.5B-7B 模型通过 RetireOPD 超越了自己的技能条件教师

**启发**：教师-学生蒸馏不是"教师越强越好"，关键是知道什么时候该让学生独立。"自适应退休"是一个优雅的设计，值得在其他训练场景中借鉴。

### 5.5 On-Demand Attention: Language Models Know When to Recall

**论文**：[arXiv:2609.20734](https://arxiv.org/abs/2609.20734)

**研究方法**：训练轻量级召回头，根据预测收益选择性调用全局注意力

**核心发现**：预训练模型的解码状态已经包含了预测全局注意力收益的信息

**启发**：不是每一步都需要全局信息。让模型自己决定何时"抬头看全局"，可以在几乎不损失性能的情况下大幅加速长上下文推理。

**启发**：世界模型不必是领域特定的。因子分解提供了一个将复杂世界拆解为可学习组件的通用框架。这对科学发现和工程应用都有深远影响。
