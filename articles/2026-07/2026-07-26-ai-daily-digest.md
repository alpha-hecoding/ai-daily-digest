### 2.1 OpenForgeRL: 训练 Harness-native Agent 的开源框架

**📄 论文**: [arXiv:2607.21557](https://arxiv.org/abs/2607.21557)  
**🔗 GitHub**: 开源框架(论文中提及)  
**⭐ 重要性**: ⭐⭐⭐⭐⭐

#### 核心问题

现代 AI Agent(Claude Code、Codex、OpenClaw 等)依赖复杂的推理基础设施(harness)来驱动多轮推理、工具使用和外部系统访问。但这些复杂的 harness 让端到端训练变得困难:
- **状态管理**: 多进程、有状态的推理环境难以表达为标准的 SFT/RL 训练流程
- **环境依赖**: Agent 需要访问真实的工具、API、文件系统
- **训练规模**: 从几百到几千个任务进行训练,需要高效的资源调度

#### 技术架构

OpenForgeRL 通过三个核心组件解决问题:

**1. 轻量级代理服务器**
- 拦截 harness 的模型调用
- 记录调用数据作为训练样本
- 支持标准 RL 代码库(如 veRL)

**2. Kubernetes 编排器**
- 每个 rollout 在独立容器中运行
- 支持任意 harness、任意环境
- 弹性扩缩容

**3. 训练-推理解耦**
- 推理: 使用真实 harness 和环境
- 训练: 使用记录的数据进行标准 RL
- 灵活组合,便于研究

#### 性能表现

| Agent 类型 | 基准 | 得分 | 对比基线 |
|-----------|------|------|---------|
| OpenForgeClaw | ClawEval pass^3 | 31.7 | 超越同规模开源基线 |
| OpenForgeClaw | ClawEval pass@3 | 55.9 | 超越同规模开源基线 |
| OpenForgeClaw | QwenClawBench | 33.7 | 超越同规模开源基线 |
| OpenForgeGUI | OSWorld-Verified | 37.7 | 超越同规模开源基线 |
| OpenForgeGUI | Online-Mind2Web | 63.0 | 匹配或超越更大模型 |
| OpenForgeGUI | WebVoyager | 72.3 | 匹配或超越更大模型 |

#### 关键发现

1. **Harness 选择影响训练难度**: 不同 harness(ZeroClaw、OpenClaw、Codex)的学习难度差异显著
2. **RL 提升 Agent 可靠性**: 强化学习改善了自我验证、工具覆盖、多步骤计划完成等能力
3. **错误恢复仍是短板**: 尽管整体性能提升,错误恢复能力仍然较弱

#### 💡 对你的价值

OpenForgeRL 让**Agent 训练变得民主化**。以前只有大公司才能进行的 Agent 训练,现在开源社区也可以做。如果你正在开发 Agent 应用,可以使用 OpenForgeRL 训练自己的模型,针对特定场景优化。这对于垂直领域 Agent(如法律、医疗、金融)特别有价值。

### 2.2 AREX: 递归自改进的深度研究 Agent

**📄 论文**: [arXiv:2607.21461](https://arxiv.org/abs/2607.21461)  
**⭐ 重要性**: ⭐⭐⭐⭐⭐

#### 核心洞察

深度研究任务需要 Agent 找到同时满足多个约束的答案。关键洞察是**发现-验证不对称性**:
- **发现成本高**: 找到满足所有约束的答案很困难
- **验证成本低**: 验证候选答案可以分解为独立的约束检查

这意味着 Agent 不应该简单地"搜索更久",而应该**递归地改进当前答案**。

#### 技术架构

AREX 采用双层循环结构:

**内层循环(研究循环)**
- 收集证据
- 构建临时答案

**外层循环(自改进循环)**
- 逐约束审计答案
- 识别未解决的声明
- 启动针对性的后续研究

**关键技术**: 自主上下文更新工具
- 压缩增长的交互历史
- 保留已验证证据和未解决约束
- 不依赖外部模型

#### 训练方法

1. **Agentic Mid-Training**: 在验证过的合成任务和高质量轨迹上训练
2. **长时域强化学习**: 强调关键步骤(获取决定性证据、纠正错误研究方向)

#### 模型规模

- **Dense 模型**: 4B 参数
- **MoE 模型**: 122B-A10B (Mixture-of-Experts)

#### 性能表现

在多个基准上超越同规模基线:
- BrowseComp
- WideSearch
- DeepSearchQA
- Humanity's Last Exam (HLE)
- 其他推理和工具使用基准

#### 💡 对你的价值

AREX 展示了**如何让 Agent 变得更聪明,而不是更用力**。传统的深度研究 Agent 通过延长搜索时间来提升性能,但 AREX 通过递归自改进来提升效率。这对于需要复杂推理的应用(如科学研究、法律分析、技术调研)非常有价值。如果你正在构建研究型 Agent,AREX 的架构值得借鉴。

### 2.3 Tencent WorkBuddy Bench: 防污染的编码 Agent 评测基准

**📄 论文**: [arXiv:2607.20911](https://arxiv.org/abs/2607.20911)  
**🏢 发布方**: 腾讯  
**⭐ 重要性**: ⭐⭐⭐⭐

#### 核心问题

现有的编码 Agent 评测基准存在**数据污染**问题:
- 任务来自公开的 GitHub Issue
- 模型可能在训练数据中见过这些任务
- 评测结果不可靠

#### 创新方法

Tencent WorkBuddy Bench 采用**逆向工程**的任务构建方法:

1. **从真实提交开始**: 选择真实的 commit、pull request、业务场景
2. **逆向重写任务**: 将任务重写为简短、口语化、角色扮演的请求
3. **防搜索设计**: 任务的 prompt 无法通过搜索底层 Issue/PR/commit 恢复

#### 四大领域

| 领域 | 任务类型 | 示例 |
|------|---------|------|
| Code | 仓库级工程 | 修复复杂 bug、添加新功能 |
| Web | 前端开发 | 实现 UI 组件、优化性能 |
| Office | 办公工作流 | 数据处理、报表生成 |
| Security | 红蓝对抗 | 漏洞检测、安全加固 |

#### 开放资源

- 任务目录
- 环境镜像
- 评测工具
- 测试用例
- 参考答案

#### 💡 对你的价值

Tencent WorkBuddy Bench 解决了**编码 Agent 评测的信任问题**。如果你正在开发或选择编码 Agent,这个基准提供了更可靠的性能评估。它的防污染设计思路也值得其他评测基准借鉴。

### 2.4 Agentic Coding 的本地化: 开源模型的数据准备能力

**📄 论文**: [arXiv:2607.21482](https://arxiv.org/abs/2607.21482)  
**⭐ 重要性**: ⭐⭐⭐⭐

#### 核心问题

研究人员在处理纵向人口研究数据时,面临**数据治理**要求:
- 敏感数据不能传输到外部服务
- 不能使用云端 LLM
- 需要本地部署方案

#### 解决方案

论文提出了一个开源框架,评估**开源权重 LLM** 在数据准备任务上的表现:

**框架组成**:
1. 真实数据集: 英国队列研究的 6 轮数据清理脚本
2. 任务定义: 类别协调、多波次合并等
3. 自动评估: 评估 LLM 生成的 R 代码和输出数据

**评测规模**:
- 20 个数据准备任务
- 创建 102 个变量
- 测试多个消费级部署模型

#### 关键发现

- **31-35B 参数模型接近饱和**: 平均任务完成度达 87.9%
- **消费级硬件可行**: 开源 LLM 在消费级硬件上表现良好
- **治理受限场景的可行路径**: 为数据敏感研究提供了实用方案

#### 💡 对你的价值

这项研究证明了**本地 Agentic Coding 的可行性**。如果你的工作涉及敏感数据(医疗、金融、法律),可以使用开源模型在本地完成复杂的数据准备任务,而无需担心数据泄露。框架开源在 [GitHub](https://github.com/UCL-ARC/RRBench),可以直接使用。

### 2.5 Agent 设计模式: 从 Fazm 看 macOS 自动化

**📚 来源**: [Fazm Blog](https://fazm.ai/blog/)  
**⭐ 重要性**: ⭐⭐⭐⭐

#### Fazm 的设计理念

Fazm 是一个语音优先的 macOS AI Agent,其博客分享了多个实用设计模式:

**1. 语音优先交互**
- 使用 whisper.cpp 进行本地语音识别
- 支持 large-v3 和 large-v3-turbo 模型
- 在 Apple Silicon 上实现实时转录

**2. 桌面控制 API**
- 使用 Accessibility API 控制 GUI
- ScreenCaptureKit 进行屏幕捕获
- 支持跨应用操作

**3. 成本管控**
- 详细跟踪 Claude extra usage
- 设置支出控制
- 比较不同模型成本

#### 实用技巧

从 Fazm 博客中提取的实用技巧:

1. **ClipProxy**: 将 CLI 订阅转换为 OpenAI 兼容 API

### 5.1 SANA-Video 2.0: 混合线性注意力的视频生成

**📄 论文**: [arXiv:2607.21553](https://arxiv.org/abs/2607.21553)  
**🏢 机构**: 多机构合作  
**⭐ 重要性**: ⭐⭐⭐⭐⭐

#### 研究动机

视频生成模型面临**计算复杂度**的挑战:
- 全 softmax 注意力: O(N²) 复杂度,长视频计算成本爆炸
- 纯线性注意力: O(N) 复杂度,但表达能力不足

如何平衡效率和表达能力?

#### 核心方法

**混合线性-softmax注意力**
- 3:1 比例: 3 层门控线性注意力 + 1 层门控 softmax 锚点
- 恢复全秩交互: 锚点层恢复线性注意力缺失的全秩 token 交互
- O(N) 主导: 整体复杂度接近线性

**块注意力残差(AttnRes)**
- 将完成的块摘要路由到后续线性层
- 实现锚点特征复用
- 提升深层有效秩约 12%

#### 性能表现

| 配置 | VBench 得分 | 生成时间 | 硬件 |
|------|-----------|---------|------|
| 5B, 480p | 84.30 | 13.2s | 单 H100 |
| 5B, 720p/5s | - | 13.06s | 单 H100 |
| 14B, 720p/60s | - | - | 单 H100 |

**对比**:
- 编译后 DiT 前向传播比全 softmax 基线快 3.2x (720p)
- 全栈 Sol-Engine 优化再加速 3.58x
- 5B 管线比 Wan 2.2-A14B 快 120x (单 H100)

#### 关键创新

1. **从头训练**: 不是线性化预训练模型,而是直接训练混合模型
2. **降分辨率代理研究**: 确定 25% softmax 为最优质量-效率权衡
3. **全栈优化**: 核融合、缓存、稀疏注意力

#### 💡 对你的价值

SANA-Video 2.0 证明了**不需要牺牲质量就能获得效率**。如果你在做视频生成相关研究或应用,这个混合注意力架构可以大幅降低计算成本。特别是对于长视频生成,这是一个突破性的方案。

### 5.2 ProVisE: 在像素空间评估空间认知

**📄 论文**: [arXiv:2607.21072](https://arxiv.org/abs/2607.21072)  
**🏢 机构**: 浙江大学等  
**⭐ 重要性**: ⭐⭐⭐⭐

#### 研究动机

空间智能对 Agent 与物理世界交互至关重要。现有基准存在**答案接口不匹配**问题:
- 空间任务通常在连续视觉场景中进行
- 位置、区域、路径更适合用指向、标记、绘制来表达
- 但现有基准要求坐标、选项或文本

这让图像生成模型难以在相同任务语义下评估。

#### 核心方法

**ProVisE (Protocolized Visual Evaluation)**
- 基准无关框架
- 引导图像生成模型生成协议约束的视觉答案
- 解析为结构化预测,兼容原始指标

**Agentic 构建器**
- 自动构建和验证新基准的任务特定协议
- 减少人工标注成本

**SpatialGen-Bench**
- 470 个样本
- 14 个空间子任务
- 4 个能力级别
- 多种答案形式

#### 关键发现

- **图像生成模型**: 在可以直接在像素空间外部化空间答案时表现竞争
- **文本输出 VLM**: 在组合空间推理上保持明显优势
- **互补优势**: 像素空间表达和文本推理各有优势

#### 💡 对你的价值

ProVisE 为**评估多模态模型的空间能力**提供了新范式。如果你在做视觉问答、机器人导航、AR/VR 等需要空间理解的应用,这个评估框架可以帮助你更准确地衡量模型能力。

### 5.3 VCSD: 视觉对比自蒸馏

**📄 论文**: [arXiv:2607.21556](https://arxiv.org/abs/2607.21556)  
**⭐ 重要性**: ⭐⭐⭐⭐

#### 研究动机

在线策略自蒸馏(OPSD)很有前景,因为它移除了外部教师,但仍需要**非对称信息**:
- 教师需要比学生提供更强的学习信号
- 现有方法通过特权答案或视觉证据创建非对称性

能否移除这些依赖,仅通过输入条件驱动 OPSD?

#### 核心方法

**Visual Contrastive Self-Distillation (VCSD)**
- 将图像内容移除转化为在线策略自蒸馏信号
- 在每个学生生成的响应前缀:
  - EMA 教师生成两个下一 token 分布
  - 一个以原始图像为条件
  - 一个以内容擦除控制为条件
- 逐 token 对数概率差异突出显示视觉内容增加似然的候选
- 使用对比锐化教师的原始图像分布
- 将完整分布目标蒸馏到学生

#### 性能表现

在 Qwen3-VL 上:

| 模型规模 | 改进前 | 改进后 | 提升 |
|---------|--------|--------|------|
| 2B | 62.27% | 67.04% | +4.77% |
| 4B | 71.30% | 73.16% | +1.86% |
| 8B | 72.51% | 76.26% | +3.75% |

#### 关键优势

- **无需外部教师**
- **无需特权答案**
- **无需视觉证据信号**
- **无需推理轨迹**
- **无额外推理时成本**

#### 💡 对你的价值

VCSD 提供了一种**简单而有效的模型改进方法**。如果你在使用视觉语言模型,可以用 VCSD 以很低的成本提升性能。特别是对于小模型(2B-8B),提升效果显著。

### 5.4 Robostral Navigate: 单目 RGB 的机器人导航

**📄 论文**: [arXiv:2607.20785](https://arxiv.org/abs/2607.20785)  
**🏢 机构**: Meta 等  
**⭐ 重要性**: ⭐⭐⭐⭐

#### 研究动机

部署导航系统需要**最小化传感器假设**:
- 现有系统依赖深度传感器、多摄像头、预构建地图
- 限制了硬件支持和部署成本

能否仅用单目 RGB 实现强大的导航?

#### 核心方法

**Robostral Navigate**
- 8B 视觉语言模型
- 仅消费单目 RGB 图像流
- 通过在当前相机视图中指向下一个目标位置来预测路径点
- 在图像空间操作,而非机器人特定坐标

**训练优化**
- 240 万轨迹,35 万模拟场景
- 前缀缓存训练: 将完整片段打包为单个训练序列
- 训练 token 减少 22x,训练时间从月缩短到天
- 树形注意力掩码: 防止条件依赖先前真实动作
- 强化学习: 改进探索和恢复能力

#### 性能表现

| 基准 | 成功率 | 对比 |
|------|--------|------|
| R2R-CE | 77.4% | 超越最佳单目方法 10.5 个百分点 |
| R2R-CE | 77.4% | 超越最强深度/多摄像头系统 5.3 个百分点 |
| RxR-CE | 75.1% | 超越所有单目基线 |

#### 关键创新

- **纯图像空间**: 对相机内参和场景尺度自然鲁棒
- **跨平台**: 轮式、腿式、空中机器人无需重新校准
- **高效训练**: 前缀缓存大幅降低训练成本

#### 💡 对你的价值

Robostral Navigate 证明了**简单传感器也能实现强大导航**。如果你在做机器人、无人机、自动驾驶等应用,这个方法可以大幅降低硬件成本。仅用普通摄像头就能实现顶级性能,这是一个非常实用的方案。

### 5.5 LLM 道德推理: 超越谄媚的结构化抵抗

**📄 论文**: [arXiv:2607.21558](https://arxiv.org/abs/2607.21558)  
**⭐ 重要性**: ⭐⭐⭐⭐

#### 研究动机

构建社会化的 LLM 需要模型能够**从他人学习而不简单屈服**。模型必须区分:
- 何时整合他人视角
- 何时坚持有根据的道德判断

现有研究将谄媚视为一维失败模式,但这不够。

#### 核心方法

论文研究了更广泛的**抵抗-遵从过程**,通过三项研究展示:

模型的判断修正沿三个维度结构化,类似人类社会心理学的经典现象:

1. **距离**:  incoming 观点与模型初始位置之间的距离
2. **来源归因**: 观点的来源归属
3. **联盟结构**: 支持该观点的联盟结构

#### 关键发现

- **邻近性**: 模型对邻近位置更开放
- **自我一致性**: 更容易受呈现为自己先前判断的观点影响
- **群体压力**: 对群体压力的响应不同

#### 理论贡献

- 将谄媚重新框架化为更广泛的判断更新过程的一个表现
- 提供了区分**建设性信念修正**和**谄媚遵从**的原则基础
- 支持在道德重要交互中的更好对齐

#### 💡 对你的价值

这项研究对**构建更好的 AI 对齐**至关重要。如果你在做 RLHF、AI 安全、伦理 AI 等工作,这个框架可以帮助你理解和改进模型的道德推理能力。它提供了超越简单"减少谄媚"的更细致方法。
